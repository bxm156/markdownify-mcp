# examples/

`upload-and-convert.ts` is the reference client for the remote server: connect over MCP Streamable HTTP, discover tools (direct or LiteLLM-prefixed), `create_upload`, stream the file with `PUT` to the returned scoped URL, `start_conversion`, poll `get_conversion_status` with backoff, then read `get_markdown` page by page (`next_offset`) into a new output file. It never overwrites output and never logs upload credentials.

Run (from the repo root, server already running), under Bun or Node 24.2+ (`engines.node`; type stripping is on by default):
`MCP_TOKEN=<token> bun examples/upload-and-convert.ts src/sample-data/test.pdf out.md`
`MCP_TOKEN=<token> node examples/upload-and-convert.ts src/sample-data/test.pdf out.md`
Env: `MCP_URL` (default `http://localhost:8000/mcp`), `MCP_TOKEN` (direct), or gateway mode with `LITELLM_API_KEY` + `MARKDOWNIFY_BASE_URL` (+ optional `MARKDOWNIFY_AGENT_TOKEN`, `MARKDOWNIFY_SERVER_ALIAS`), `CONVERSION_DEADLINE_MS` (default 300000). Plain HTTP only for loopback.

CI: remote-mvp.yml runs it against the single-tenant container (`MD_API_KEY`) and the multitenant container (agent `a` from `MD_TEST_AGENT_KEYS`); docker-publish.yml runs it against the multitenant candidate; jwt-http-smoke.ts runs it in gateway mode. The single-tenant step also runs it under plain Node (`node --experimental-strip-types --no-warnings`) and, via `docker run --network container:markdownify-ci ... node examples/upload-and-convert.js`, inside the image. `bun run typecheck` type-checks it.

Image: the `build` stage of `Dockerfile.remote` compiles it with `bun build --target=node --packages=external` to `build-examples/upload-and-convert.js`, and the runtime stage copies that to `/app/examples/upload-and-convert.js` (the raw `.ts` is not shipped). `@modelcontextprotocol/sdk` stays external and resolves from the runtime `/app/node_modules` (a production dependency), and `/app/package.json` (`"type": "module"`) makes the `.js` ESM. Usage: `docker run --rm --network container:<server> -e MCP_TOKEN -v "$PWD/in:/in:ro" -v "$PWD/out:/out" --user "$(id -u)" <image> node examples/upload-and-convert.js /in/report.pdf /out/report.md`.

Rule: keep it self-contained: the only imports are `@modelcontextprotocol/sdk` and Node built-ins, and it must run under both bun and node (type annotations only; no enums, namespaces or parameter properties, which Node's type stripping rejects). Never import from `src/`: the image has no `src/` and plain `node` cannot resolve `../src/remote/*.js`. Do not add packages or Bun-only APIs. Error guidance is a condensed local table of the server's `error_info` codes (full catalogue: `src/remote/errors.ts`, `docs/ERRORS.md`); when you add a code that this flow can hit, add it to the table. Keep the CI-asserted output ("Test PDF content" from the sample PDF) and the usage line stable.
