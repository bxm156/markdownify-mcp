# src/ (local stdio MCP server)

Scope: the files directly in `src/`. `src/remote/` is the separate HTTP service and has its own notes. The one cross-dependency: `remote/converter.ts` and `remote/health.ts` import `resolveMarkitdownPath` from `utils.ts`, so changing it affects both servers.

## Purpose and entry point
- Fork of upstream `zcaceres/markdownify-mcp`. Package `mcp-markdownify-server`; `bin` is `dist/index.js` (`tsc` output, `#!/usr/bin/env node`). `engines.node >= 24.2`.
- `index.ts`: sets `PYTHONUTF8=1`, installs the shutdown handlers, calls `warnIfProxyConfigured()` (`proxyWarning.ts`, stderr note: URL downloads never use `HTTP(S)_PROXY`), connects `createServer()` to `StdioServerTransport`. stdout carries the protocol: never `console.log`, use `console.error`.
- Shutdown: converters run in their own process group, so signals sent to the server (or to the terminal's group on Ctrl+C) do not reach them. `installShutdownHandlers` adds `process.once` handlers for SIGHUP, SIGINT and SIGTERM that call `killActiveTools()` and then `process.exit(128 + signal number)`: 129, 130, 143 (an exit status, not a re-raised signal, so it behaves the same under Node, Bun and on Windows). A `process.once("exit")` handler calls `killActiveTools()` again for any other exit (stdin closed, fatal error); it must stay synchronous. Only `index.ts` installs handlers: importing `Markdownify.ts` (tests do) installs none. SIGKILL of the server cannot be handled; its converters then run until their own timeout. A signal exit skips `withStagingDir`'s `finally`, so that call's staging directory stays in `os.tmpdir()`.
- Must run under the user's Node or Bun (`bun start` = `bun dist/index.js`). macOS, Linux and Windows are all supported here (`setup.sh` / `setup.bat`; `preinstall.js` picks one). Tests run under Bun (`bun test`).
- Build: `bun run build` (tsc to `dist/`, test files excluded by `tsconfig.json`); `bun run typecheck` uses `tsconfig.check.json`.

## Tools and dispatch
- `tools.ts`: 11 tools, hand-written `inputSchema` + `readOnlyHint` annotations (`openWorldHint` on url tools and git). url tools: `youtube-`, `bing-search-`, `webpage-to-markdown`. filepath tools: `pdf-`, `image-`, `audio-`, `docx-`, `xlsx-`, `pptx-to-markdown`. Also `git-repo-to-markdown` (`url`, `branch?`, `compress?`) and `get-markdown-file` (`filepath`). `ListTools` returns `Object.values(tools)`, so every export of `tools.ts` is a tool.
- `schemas.ts`: strict zod schema per tool (`urlArgs`, `filepathArgs`, `gitRepoArgs`; `branch` is refined with `gitRefProblem`, and `""` is still accepted but transformed to `undefined` (= default branch), so it never reaches `fromRepo`), looked up by `getToolArgumentSchema(name)` (`Object.hasOwn`, so `toString` etc. are not tools). `tools.test.ts` asserts required keys, property keys, types and `additionalProperties: false` agree with `tools.ts` (via `z.toJSONSchema(schema, { io: "input" })`, since transforms have no output JSON Schema). Edit both files together.
- `server.ts`: `runners` map (name -> `Markdownify.*`) + schema. Unknown name (no schema or no runner) -> `Error: Tool not found`. Bad args -> `Error: Invalid arguments: <path>: <msg>` (first issue only); missing/empty `url`/`filepath` keep "URL is required for this tool" / "File path is required for this tool". All failures are `{content:[{type:"text",text:"Error: ..."}], isError:true}`, never protocol errors. Success: optional `Output file: <path>` text first (only `get-markdown-file` sets `path`), then the text. Server version comes from `package.json` via `readPackageVersion()` (`../package.json` relative to the module; same from `src/` and `dist/`); `download.ts` has its own copy for the User-Agent.
- New tool = entry in `tools.ts`, `toolArgumentSchemas`, `runners`, plus the count/name lists in `tools.test.ts`.

## Markdownify.ts
- `toMarkdown({url|filePath, timeoutMs?})`: any error is rethrown as `Processing to Markdown failed: ...` (server.ts adds the `Error: `). `get` and `fromRepo` do not wrap.
- URL mode: `safeFetch` (30 s `AbortSignal.timeout` over the whole exchange, up to 10 redirects; **each hop** runs `resolvePublicAddresses` then `download.fetch(url, addresses, signal)`; HTTP >= 400 -> `Fetching <redacted> failed with HTTP n`) -> `readBodyWithLimit` (50 MiB; checks Content-Length, then counts streamed bytes anyway) -> body written to `input.<ext>` in a staging dir. `inferExtensionFromUrl` returns `pdf` when the parsed URL's pathname ends in `.pdf` (case-insensitive; query/fragment ignored), otherwise `html` (also for an unparsable string).
- File mode: `expandHome`, then `openLocalFile` (both with and without an allowlist), then `stageOpenedFile` copies exactly the opened bytes (via `readOpenedFile`, offset reads, cap re-enforced as it reads) to `<staging>/input<original ext>`; markitdown only ever sees that private copy. `MAX_LOCAL_FILE_BYTES` = 50 MiB (`utils.ts`), also the URL cap.
- `withStagingDir(fn, prefix = "markdown_output_")`: `fs.mkdtemp(os.tmpdir()/<prefix>*)` per call, removed in `finally` (`rm` with `maxRetries`). The file handle is closed in its own `finally`.
- `runTool(file, args, {maxBuffer, timeoutMs, env?})` runs every external tool (`spawn`, no shell, stdin ignored, stdout/stderr collected as bytes and decoded UTF-8). On POSIX it spawns `detached` (own process group) and on timeout `killProcessTree` SIGKILLs the group (`process.kill(-pid)`); on win32 it runs `taskkill /T /F /PID <pid>` (`%SystemRoot%\System32\taskkill.exe` via `spawnSync`, no shell, 10 s limit) to end the child's descendants too. Either way it falls back to `child.kill("SIGKILL")` when the tree kill fails (group gone, taskkill missing or non-zero). The pipes are destroyed too so it settles once the direct child is gone. `killProcessTree` is synchronous (it runs in the "exit" handler).
- Active runs: `runTool` adds each spawned child to a module-level `activeTools` set and removes it when the run settles; `killActiveTools()` (exported, synchronous) kills every registered tree with `killProcessTree`, empties the set and returns the count. The killed runs reject with `Command failed` (signal SIGKILL), not `timedOut`. Errors mirror execFile's: spawn errno (`ENOENT`), `Command failed: <cmd>\n<stderr>` with `code`/`signal`, `ERR_CHILD_PROCESS_STDIO_MAXBUFFER` (also kills the group), and `timedOut: true` for a timeout. execFile cannot be used: it does not pass `detached` and kills only the child.
- `_markitdown(filePath, tempDir, projectRoot, timeoutMs)`: `runTool(resolveMarkitdownPath(projectRoot), [path])` with `TMPDIR`/`TEMP`/`TMP` set to `tempDir` (the call's staging directory, which also holds the input copy; the rest of `process.env` is inherited), so its temporary files go when the staging directory is removed, 50 MB maxBuffer, timeout = `converterTimeoutMs()` (`MD_CONVERTER_TIMEOUT_MS` if a positive number, else `CONVERTER_TIMEOUT_MS` = 5 min) -> "markitdown timed out after N ms" (detected via `err.timedOut`); stderr is ignored (non-fatal warnings), non-zero exit rejects; ENOENT gives a platform-aware setup hint (`.venv/bin/pip` or `.venv\Scripts\pip`, `markitdown[all]==0.1.5`, the version setup.sh/setup.bat/Dockerfile pin); output starting `<!doctype`/`<html` in any case -> "raw HTML ... SPA" error (`isUnconvertedHtml`). `projectRoot` = parent of the module dir.
- `resolveMarkitdownPath`: `MARKITDOWN_PATH` -> `<root>/.venv/bin/markitdown` (`.venv/Scripts/markitdown.exe` on win32) if it exists -> bare `markitdown` on PATH. `resolveRepomixPath` is the same shape: `REPOMIX_PATH` -> `node_modules/.bin/repomix` -> `repomix`.
- `fromRepo`: `validateGitRef(branch)` when non-empty (before any DNS), then `await validateRepoUrl(url, AbortSignal.timeout(30 s))`, then repomix `--remote <url> --style markdown --stdout --quiet [--remote-branch b] [--compress]` via `runTool`, 100 MB maxBuffer, same timeout and process-group kill as markitdown ("repomix timed out"; its git children die too), empty stdout is an error. repomix (no `--temp-dir` option) clones into `os.tmpdir()/repomix-*`, so it runs inside `withStagingDir(..., "markdownify_repomix_")` with `TMPDIR`/`TEMP`/`TMP` pointing there: a killed clone is removed with it.
- `get`: `.md`/`.markdown` only, case-insensitive ("Required file is not a Markdown file."), `openLocalFile`, UTF-8 read via the handle (`readOpenedText`), ENOENT -> "File does not exist", returns `path: filePath` as given.

## utils.ts: trust boundaries
- Allowlist: `MD_ALLOWED_PATHS` (else legacy `MD_SHARE_DIR`), split on `path.delimiter`, `~` expanded. A variable that is empty, whitespace or lists no directory counts as unset (so `MD_ALLOWED_PATHS=""` falls through to `MD_SHARE_DIR`). Both unset = any readable file. `assertPathAllowed` only says where a path points *now*; anything that reads must go through `openLocalFile`.
- `openLocalFile` order: (allowlist only) `assertPathAllowed`, `realpath`, `assertRealPathAllowed`; then `lstat` pre-filter (`assertLooksLikeRegularFile`: FIFOs/sockets/devices are never opened); open `O_RDONLY|O_NONBLOCK` (+`O_NOFOLLOW` with an allowlist; ELOOP/EMLINK -> "changed while it was being opened"); then the handle's `fstat` must be a regular file <= cap; (allowlist only) `resolveOpenedFile` (Linux: `readlink /proc/self/fd/N`, deliberately not realpath; elsewhere or without /proc: `realpath` + dev/ino must equal the handle's) and `assertRealPathAllowed` again. Rule: the decision is about the opened file, never a path that could be swapped later.
- `resolvePublicAddresses(url, signal)` is the SSRF guard: http(s) only, no userinfo, blocked hostnames (`localhost`, `*.localhost`, `metadata`, `metadata.google.internal`, trailing dot stripped), IP literals and every DNS answer (`all:true, verbatim:true`, abortable via `withAbort`) must be public, any private answer or lookup failure -> "potentially dangerous". `isPrivateAddress` handles IPv6: `::`, `::1`, fc00::/7, fe80::/10, fec0::/10, IPv4-mapped/translated/compatible, 64:ff9b::/96 NAT64 (embedded IPv4 is checked) and all of 64:ff9b:1::/48 (rejected wholesale); IPv4 uses `private-ip`. Rule: only addresses returned here may be dialled; `validateUrl` is the no-pinning variant. `redactUrl` (origin+path) for every URL in an error.
- `validateGitRef` / `gitRefProblem`: git check-ref-format rules plus no leading `-` (repomix runs `git fetch --depth 1 origin <ref>` without `--`, so `--upload-pack=<cmd>` would execute): non-empty, <= 255 chars, no leading `-`/`.`, no control chars/space/DEL, no `..`, `@{`, `\`, `~`, `^`, `:`, `?`, `*`, `[`, no empty component, no component starting `.` or ending `.lock`, no trailing `/`/`.`, not `@`.
- `validateRepoUrl(url, signal?)` is **async**: non-empty; `repomix.parseRemoteValue` must accept it; the input and repomix's rewritten clone URL must be http(s) when they contain `://`; a ref embedded in the URL (`/tree/<ref>`, `/commit/<sha>`, which repomix uses when no branch is given) must pass `validateGitRef`; every host (as written and as rewritten) must be in `getAllowedGitHosts()` (`MD_GIT_HOSTS` comma list, exact case-insensitive match, default `DEFAULT_GIT_HOSTS` = github.com, gitlab.com, bitbucket.org + `www.`; `*` = any host); SCP `git@host:path` only for explicitly listed hosts (never under `*`, ssh_config aliases); then `resolvePublicAddresses("https://<host>/")` must succeed. It is a pre-check, not a pin: repomix/git re-resolve and follow redirects. Rule: nothing else reaches repomix's argv.

## download.ts: pinned Happy Eyeballs fetch
- Imports nothing local on purpose (tests load it directly in Node via `--experimental-strip-types`): keep it erasable-TS only (no enums, parameter properties) and dependency-free.
- `download.fetch(url, addresses, signal, {connectTimeoutMs, attemptDelayMs})` replaces global `fetch` so DNS is pinned to the vetted addresses. We open the sockets (`openSocket`: `net.connect`/`tls.connect` with a custom `lookup` answering only the chosen address on `nextTick`, `autoSelectFamily:false`, SNI = hostname unless IP literal); the winner is handed to `http(s).request` via `createConnection`. Request headers: `Connection: close`, `Accept-Encoding: identity`, `User-Agent: markdownify-mcp/<version>`; gzip/br/deflate responses are still decoded (single encoding only). Proxies are intentionally unsupported.
- `connectFirst` (RFC 8305): `interleaveFamilies` alternates v6/v4, v6 first unless `familyMemory` (per hostname, LRU of `CONNECTION_MEMORY_LIMIT`=256, only learned from dual-stack races; `resetConnectionMemory` for tests) says v4 won last time. A new attempt starts every `ATTEMPT_DELAY_MS`=250 or at once when the previous one fails. Each attempt has a `CONNECT_TIMEOUT_MS`=5000 budget (covers TLS handshake for https), **except the last possible attempt**, whose budget is lifted so it runs to the caller's deadline. First `connect`/`secureConnect` wins; all others are destroyed with timers and listeners removed before `onWinner`.
- Errors: `TRY_NEXT_ADDRESS_ERRORS` (ECONNREFUSED, EHOSTUNREACH, ENETUNREACH, ETIMEDOUT, EADDRNOTAVAIL, EAFNOSUPPORT, EINVAL, ECONNRESET, EPIPE, ECONNABORTED) fall through; `isVerificationError` (ERR_TLS_*, ERR_SSL_*, *CERT*, UNABLE_TO_*, ...) and unknown codes end the fetch immediately and never try another address. All addresses failing, or the deadline passing mid-race, gives `ConnectFailedError` (`code ERR_ALL_ADDRESSES_FAILED`, `attempts[]`, `untried`). After a winner exists nothing is retried.

## Invariants for changes
- No Bun-only APIs in non-test code (`Bun.*` is test-only); the shipped server must run on Node >= 24.2.
- Never run markitdown/repomix on a path that was not opened and validated by `openLocalFile`; never reopen a path after validating it.
- Staged copies keep the original extension (markitdown chooses the converter by it); URL input uses `input.<pdf|html>`.
- Temp dirs are created only through `withStagingDir`; cleanup stays in `finally`.
- Keep per-hop SSRF re-validation and pinning in `safeFetch`; do not add a code path that calls global `fetch` or follows redirects itself.
- Do not widen the argument schemas: strict, per tool, no shared catch-all. Keep `tools.ts` and `schemas.ts` in sync.
- Every external run (markitdown, repomix) goes through `runTool`: a timeout with SIGKILL of the whole process group (POSIX) or `taskkill /T /F` (win32), registration in `activeTools`, and a private `TMPDIR` (the staging directory); every git ref and repository host is validated before repomix starts (`validateGitRef`, `validateRepoUrl`), in the schema and again in `fromRepo`. Tests stub DNS (`spyOn(dns.promises, "lookup")`) for any `fromRepo`/`validateRepoUrl` call.
- Keep `download.ts` free of local imports; keep `ConnectFailedError`/redaction behaviour (no credentials or query strings in messages).

## Testing notes
- `bun test src/utils.test.ts src/Markdownify.test.ts src/download.test.ts src/server.test.ts src/tools.test.ts` is what `.github/workflows/cross-platform.yml` runs on macOS and Windows (with markitdown 0.1.5 installed, plus `bun run typecheck`); Linux CI runs the full `bun test`. `index.test.ts` spawns the entry under `process.execPath` and speaks JSON-RPC over stdio.
- `converterTest` (`Markdownify.test.ts`) skips when no markitdown is found (same lookup as production, `Bun.which` for a bare name). `sample-data/` files other than `test.pdf` are tiny ASCII placeholders, not real Office/image files; assertions rely on markitdown's plain-text fallback.
- `networkTest` (git clones via repomix) runs only when `MD_TEST_NETWORK` is exactly `1`.
- `src/test-helpers.ts` (excluded from the build, no Bun APIs): `isRunning`, `waitUntil`, `killQuietly`, shared by `Markdownify.test.ts` and `index.test.ts`.
- The "external tool stubs" block (`Markdownify.test.ts`, POSIX only) points `MARKITDOWN_PATH`/`REPOMIX_PATH` at shell stubs that record their argv, to prove a rejected branch/host never starts repomix and to test timeouts with a tiny `timeoutMs`. Tree-kill tests use a stub that backgrounds `sleep 30`, records both PIDs and `wait`s; after the timeout both must be gone (`isRunning` treats an unreaped zombie in `/proc/<pid>/stat` as dead, since PID 1 in some containers does not reap). A fake-clone stub creates `$TMPDIR/repomix-*/marker` to prove the private temp dir is removed after a timeout and after success; a markitdown stub does the same with `$TMPDIR/marker` and checks `TMPDIR` is the staging dir. `killActiveTools` is tested against a running stub tree.
- The win32 branch of `killProcessTree` is only unit-tested, never run on Windows: `_processKillTestHooks` (`platform`, `taskkill`) injects the platform and a fake taskkill runner with a fake child ("killProcessTree on win32" in `Markdownify.test.ts`); one POSIX test uses the real runner where no `taskkill.exe` exists to prove the fallback. Tests must delete the hooks in `afterEach`.
- `index.test.ts` sends SIGTERM, SIGINT and SIGHUP to the server (under Bun) while a stub converter and its grandchild run, and expects status 143/130/129 and both processes dead.
- `_fileAccessTestHooks` (`afterValidate`, `afterOpen` in `utils.ts`) let tests swap files/symlinks at exact points in `openLocalFile` without sleeps; tests must delete them in `afterEach`. Symlink, FIFO, rename-ancestor tests use `posixOnly` / `describe.skipIf(win32)`; the `/proc/self/fd` variants skip off Linux; a platform-neutral dev/ino test runs everywhere.
- Tests redirect `TMPDIR/TEMP/TMP` to a private dir and assert nothing is left behind.
- `download.test.ts` runs mostly under Bun against local servers on 127.0.0.1 with `.invalid` hostnames; `interceptConnects` wraps `net.connect`/`tls.connect` so the pinned lookup never answers for "stalled" addresses (simulates dropped SYNs), or refuses/delays chosen ones; TLS stalls use a self-signed `tls.invalid` server. Tests that need Node semantics (sync lookup crash, timer leaks, abort bridge) spawn `node --experimental-strip-types` on `download.ts` via `runUnderNode`.
